# Official SF1, paged

> **2026-08-29.** The first measurements on an **official** LDBC corpus, and
> the first on the paged serving path.

## Method

| | |
|---|---|
| **Corpus** | **Official** LDBC SNB Interactive Datagen output at SF1, converted by `datagen2jsonl` — **3,181,724 nodes / 17,256,038 relationships**, 9,892 persons |
| **Host** | a dedicated benchmark host: 6-CPU cgroup, 40 GiB limit, in-host client, statically linked binaries |
| **Server** | paged serving mode — `--paged-dir`, an 8 GiB block cache, a raised seal threshold |
| **Storage** | segments on local disk, reads faulting in through the block cache |
| **Durability** | none — seal boundaries only; the benchmark reloads from the archive |

Note the corpus line. Everything else in this book generated by `snbgen` is
*synthetic data on an SNB-like schema*; **this run used real Datagen output**,
with provenance and byte verification recorded alongside it. The distinction is
kept because one of them may be called an LDBC result and the other may not.

## The epoch note

The document opens with a warning to its own future readers:

> These are the **first** numbers on an official corpus and the **first** on the
> paged path. They are **not comparable** to the resident-store numbers that
> preceded them.

Two variables changed at once — the corpus *and* the storage path — so this run
establishes a new baseline rather than extending an old one.

Saying so in the document is what stops someone later placing these figures in a
table beside earlier ones and reading a regression or an improvement that is
neither.

## Why paged, and what it costs

Paged mode is the only way to serve a corpus of this size from a bounded memory
budget: sealed segments live on disk and are read block-by-block through the
cache, so the **working set** rather than the corpus sets the floor.

The trade is stated rather than buried: **no WAL, durability at seal boundaries
only.** For a benchmark that reloads from an archive, that is free. For a
production deployment it is the reason
[Durability and recovery](../using/durability.md) demonstrates the loss rather
than describing it.

The raised seal threshold is worth noticing too: it means more sits in the
volatile tail, which is a throughput choice a benchmark can make and a durable
deployment cannot.

## What it established

The paged path serving an official SF1 corpus at all — 3.18M nodes and 17.26M
relationships from a 6-CPU host with an 8 GiB cache.

The current standing on this corpus is on
[How Engram is measured](./index.md), and its principal caveat comes from here:
**SF1 only.** The programme's plan called for SF1 → SF100, and only SF1 has run.
